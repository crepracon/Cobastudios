# CLAUDE.md — Coba Studios Estimator

Guidance for Claude Code (and any AI tooling) working in this repo.

## What this is
A pricing calculator + job/customer database for Coba Studios, a print shop in Brockville, Ontario. **One self-contained file: `index.html`** — embedded CSS and JS, no build step, no dependencies beyond CDN fonts. All prices CAD with 13% HST. Deployed via GitHub Pages: every push to `main` updates the live app at https://crepracon.github.io/Cobastudios/

## The owner / how to work with him
Chris is a hobbyist developer learning as he builds. Pragmatic and iterative: get it working first, polish later. Give structured options, not open-ended questions. Briefly explain new concepts when they first appear — he wants to understand his own codebase. When a bug is fixed, give the one-paragraph version of what actually went wrong.

## Architecture
- **Tabs:** Paper Estimator, DTF Heat Transfer, Vinyl/Roland, UV Printing, Epson, Jobs, Inventory
- **localStorage keys:**
  - `coba-inventory-v2` — materials inventory (vinyl, substrates, paper). Papers are structured (v33): `{brand, weight, unit ('#','pt','mil','gsm',''), size, cost, supplier, unsure[]}`; `paperMigrate()` converts old name-only entries (known names via `PAPER_SEED`, others parsed), `paperLabel()` builds the dropdown text, `unsure` marks fields shown with a yellow ? until edited. Epson papers (`epsonPapers`, read by the art beta) keep `name`. Has migration logic; any schema change MUST migrate, never break saved data. New default items reach saved inventories through `invAddOnce(tag, list, codes)` (v32): copied from the defaults by product code, placed after their neighbour, tagged in `inventory.added` so an item Chris removes stays removed. Papers have no product code, so new default papers use `invAddPaperOnce(tag, match)` (v37) instead, matched by brand + size. A one-time change to papers already saved (e.g. a new invoice price) goes through `invUpdatePaperOnce(tag, pick, apply, match)` (v38), also tagged, so a price Chris edits afterwards is never overwritten.
  - `coba-jobs-v1` — customers + saved estimates (full snapshots: panel innerHTML + field values + JS row-state vars). Same rule: migrate, never break. With cloud sync on, this becomes a local cache of the cloud list.
  - `coba-fb-config-v1`, `coba-jobs-cloud-joined-v1`, `coba-jobs-cloud-lastsync-v1` — cloud sync config and per-device sync state.
- **Cloud sync (v27, optional):** Firebase Firestore + email/password Auth, SDK loaded by dynamic `import()` from gstatic. The project config (`coba-studios-estimator`) is built in as `FB_CONFIG_BUILTIN`, so each device only signs in; if Firebase can't load (offline), the Jobs tab falls back to the local copy. Collections: `customers/{id}` and `estimates/{id}` (`cid` links to customer); the full object is stored as a JSON string in a `json` field (avoids Firestore's nested-array limits), with `name`/`title`/`status`/`date` copied out for readability in the console. `jobsSave()` → `cloudPush()` diffs `jobsData` against `cloudSent` and writes only changed docs; `onSnapshot` listeners rebuild `jobsData` via `cloudBuild()`. Mutations must keep going through `jobsSave()`, and confirm-dialog callbacks must re-find objects by id (the list may be rebuilt while a dialog is open). Access is limited by Firestore rules (email allowlist) — the web config itself is not a secret.
- **Jobs workflow (v33):** customer bar has a Job title box (`cb-title`); Save estimate updates the job opened with Load (`jobsActive = {cid, eid}`, same customer + same tab) and otherwise saves a new one; Duplicate and New estimate clear `jobsActive`. Statuses are `Waiting` / `In Production` / `Done` (`JOBS_STATUSES`, coloured dots); `jobsStatusNorm()` maps the old Quote -> Waiting and Approved -> In Production for display and on change, and `jobsMergeData()` normalises incoming jobs. Cloud docs of old jobs keep the old status names until someone changes them (no mass rewrite). Each new job stores `taken` (ISO date + time); old jobs show their date.
- **UV Printing (v33, xTool O1 Omni):** one row type (`u` prefix, `uRows`/`uId`, `uCalc()`), priced by sq ft or per item, White? / Primer? per row, optional xTool Studio ink $ and minutes per row, job setup fee (added or minimum), shop labour in cost. Cost per sq ft breakdown in UV settings (calibrated Oct 2026 from xTool Studio screenshots). Registered in `JOBS_TABS`, `SNAP_STATE`, `SNAP_TOTALS`, `SNAP_CALCS`.
- **UV Printing > Coasters (v34):** own on/off section (`uc-on`, rows `uc` prefix, `ucRows`/`ucId`, saved in `SNAP_STATE.uv`). Ceramic tiles only, compared like for like with VistaPrint ceramic coasters (cork back). Price: `uc-mode` = `market` (VistaPrint price at that quantity x `uc-pct` %) or `each` (`uc-each`). Coaster prices are all-in: the job setup fee is only added when the job has UV item rows. Cost = UV cost model (round tiles print pi/4 of the square) + tile + primer, mat once per job, shop labour shared per piece; market bar uses `stratAdvice()` (default Compete). With coasters off or empty, UV numbers are exactly the v33 ones. Pricing integrity (v36): each coaster row keeps the VistaPrint price it was quoted at (hidden `<id>-mb` = VistaPrint each, `<id>-ms` = the quantity it was for; `ucMarketEach()`), so a price refresh never changes a saved quote; changing the quantity re-prices the row, and a kept price is flagged in the row tooltip and market bar. Rows saved before v36 get the two fields on first open, seeded from their saved VistaPrint cell.
- **Paper > Calendar / Brochure references (v35):** two `no-print` boxes above Lamination (`p-cal-on`, `p-bro-on`, class `ref-section`). Reference only: they never change pCalc's numbers; `pRefCalc()` runs at the end of `pCalc()` and compares at **Finished pieces** (your quote and cost divided by it vs VistaPrint each). Calendar types come from the `market-print` sellers (wall 5 sizes, desk 2, poster, magnetic, bookmark; list price, sale shown when captured); brochures by fold / flat size / paper (standard stocks) with the other papers listed. Strategy defaults: calendars Defend, brochures Compete. Paper jobs saved before v35 get the boxes back on reopen (`pRefEnsure()` in `snapRestore`), switched off.
- **VistaPrint print ladders (v34):** `<script type="application/json" id="market-print">` (calendars, coasters, brochures; grid format `sellers[].sizes[].ladder`), read once into `MKP`; `mkpTier(ladder, q, col)` = VistaPrint's cost for q = the cheapest way to get at least q (q at the unit price of the break at or below q, or the next break's total, e.g. 10 brochures = their 25 for $40.29); col 2 = sale price where captured. Written only by `tools/market-refresh/print/apply-print.js` from `tools/market-refresh/print/data/`; separate from the sticker `market-data` block. Refreshed by the same scheduled task as stickers (v36): `collect-vistaprint-print.js` in the built-in browser (clicks size / paper radios like a customer, reads the quantity labels) -> `build-print.js` (holds >30% moves, sale-like uniform drops, partial lists; `--accept id` after Chris checks) -> `apply-print.js`; runbook `tools/market-refresh/print/README.md`.
- **Lost-work lesson (Oct 2026):** the UV tab, job title box, statuses and paper layout were built Oct 20-21 on a Claude-published copy that was never pushed; v27 was then uploaded on top of v26 and they vanished from the live app until v33 restored them by three-way merge. Previews are previews: every approved change must be committed and pushed here.
- **Dynamic rows:** DTF/Vinyl/UV/Epson tabs build rows in JS with module-level `let` arrays and id counters (e.g. `dGarmentRows`, `gId`). The Jobs snapshot system (`SNAP_STATE`) saves/restores these — if you add a new dynamic-row feature, register it there or snapshots will silently corrupt.
- **Calc pattern:** inline `oninput="xCalc()"` handlers per tab (`pCalc`, `dCalc`, `rCalc`, `eCalc`). Logic should stay in these functions, separate from display.
- **Sticker market pricing (v28, Vinyl / Roland > Stickers):** `Pricing:` select `r-stk-mode` = `market` (default) or `classic` (the old markup tiers). Market mode quotes each sticker row from competitor price ladders in `<script type="application/json" id="market-data">` (just above the main script), like for like on lamination: laminate ticked compares only laminated products (StickerYou, Sticker Mule die cut), unticked only unlaminated ones (Sticker Mule Economy, VistaPrint). Engine is `const MKT` plus the `rStk*` helpers right before `rCalc()`. Settings in the Roland settings panel: `r-stk-at` (market middle/low/high/one seller), `r-stk-pct`, `r-stk-round`, `r-stk-min`, `r-stk-warn`. Sizes with no market data fall back to classic for that row. Market check box `r-stk-mkt` is `no-print`.
  - Pricing integrity: each sticker row has hidden `<id>-mb` (market price used) and `<id>-ms` (signature `w|h|q|lam|at`). If the signature is unchanged the stored price is reused, so a saved job reopens at its quoted market price even after a data refresh; editing the row re-prices it. Jobs saved before v28 have no `r-stk-mode` and reopen in the old classic layout; `resetRoland()` restores the v28 layout from `R_PANEL_PRISTINE`.
  - Never hand-edit the prices; the refresh tool (`tools/market-refresh/`) updates the JSON block in `index.html` and `beta/index.html` together.
- **Page frame (v31):** `.wrapper` is 1280px and holds every tab. Until v31 a stray `</div>` in the Paper panel closed it early (all tabs except Paper rendered full width, and Paper's New estimate / Print buttons showed on every tab). Paper jobs saved before v31 were captured from that broken markup; `pPanelRepair()` (called in `snapRestore` for paper) moves the stray nodes back into `.panel-body` and restores the action bar. When editing markup, check the `<div>` balance of each panel.
- **Laminate dropdowns (v30):** on Stickers and Signage the laminate is chosen in the dropdown alone (`r-stk-lam-type`, `r-sgn-lam-type`, first option "None (no laminate)"). Each has `data-drives` naming a hidden checkbox (`r-stk-lam`, `r-sgn-lam`) that the rest of the code still reads; `rCalc()` sets every driven checkbox from its dropdown first. Panels saved before v30 have no `data-drives`, so their visible checkbox still decides (pricing integrity). `resetRoland()` restores the pristine panel when any of these markers is missing.
- **Signage substrate dropdown (v39):** same pattern for the board: `r-sgn-sub` has `data-drives="r-sgn-sub-on"` (now a hidden checkbox), first option "None (no substrate)" (set in `rBuildSubstrateOpts()` when the select has `data-drives`). Until v39 the board needed a separate visible checkbox, and a board shown in the dropdown with the box unticked was silently left out of the cost. Panels saved before v39 have no `data-drives` on `r-sgn-sub`, so their visible checkbox still decides; `resetRoland()` restores the pristine panel when that marker is missing and sets the substrate back to None.
- **Signage (v29, Vinyl / Roland > Signage):** laminate `r-sgn-lam-type` (inventory items with "lam"; `rSgnLamDefault()` picks Matte Laminate once per fresh panel, marked with `data-init`). Each row has a Sides select `<id>-sd`. Cost per sq ft = (vinyl + ink + laminate) x sides + board; retail = signage rate x (2F+B)/(F+B) for 2 sided (F = face, B = board; exactly 2x with no board), 1 sided unchanged. Jobs saved before v29 have no laminate box or Sides and price as before.
  - Row ids: signage rows are `sg0, sg1...` (`rGId` counter). Before v29 they were `g0, g1...`, the same ids as DTF garment rows, so `getElementById` returned the DTF inputs (signage read the garment qty and wrote into the DTF table). `rSgnMigrateIds()` (called from `SNAP_STATE.vinyl.set`) renames old jobs' rows when reopened. Dynamic-row id prefixes must be unique across ALL tabs: s, b, c, sg (Vinyl), g, i (DTF), u, uc (UV), lam, el, ep, ea.

## Hard rules
1. **Validate every change:** extract the `<script>` contents and run `node --check` before committing. For anything touching stickers or market data also run `node tools/market-refresh/smoke-estimator.js`. Jobs and cloud sync: `NODE_PATH=<dir with jsdom> node tools/smoke-jobs.js` (fake Firestore shared between jsdom windows: save / update in place / duplicate, status / notes / delete propagation, offline save pushed on reconnect, first-time merge, UV jobs across devices, paper inventory migration) — extend it when touching the Jobs module. UV coasters and the Paper calendar / brochure references: `NODE_PATH=<dir with jsdom> node tools/smoke-uv-paper.js`.
2. **Known landmines (all three have caused real bugs):**
   - No special characters (multiplication sign, middle dot, curly quotes) inside JS **string literals** — plain ASCII only. HTML entities in markup strings are fine.
   - When inserting code near constant declarations (e.g. `const PM=3, TM=5;`), verify they survive the edit. This has been dropped twice.
   - Unicode escape sequences (backslash + u + four hex digits) inside JS strings get turned into the literal character by some write paths (the GitHub connector, file-writing tools), which breaks the ASCII rule above. Build symbols with `String.fromCharCode(...)` instead.
3. **No new dependencies.** The file must stay self-contained and offline-capable. (Deliberate exception: Firebase for Jobs cloud sync, loaded only when configured.) If something truly can't be done in plain HTML/CSS/JS, explain the trade-off first.
4. **Small steps, verified.** One change at a time. Multi-section changes: state the plan first.
5. **Git:** commit at every working state with a short message. Tag milestones (`v23`, `v24`, ...). Never edit the only working copy. No secrets in the repo — the file is client-side and publicly hosted.
   - Tags/releases: Claude's cloud sessions can push branches but not tags (refused by the session's git proxy). Publish milestones from GitHub's **New release** page in the Claude desktop app's built-in browser, which is signed in as crepracon: `https://github.com/crepracon/Cobastudios/releases/new?tag=vNN&target=<full commit sha>&title=...&body=...`, then **Publish release**. Releases are public, so ask Chris first (a "publish the release" in his request counts). The session's safety check may block Claude's own Publish click (it did on Nov 2 2026, v33-v36): then open one prefilled form per release in the built-in browser (`tabs_create` + `navigate`; `preview_start` reuses the tab), check each form's tag / target with FormData, bring them to the front one at a time while Chris clicks **Publish release** in version order, and confirm with `gh api repos/crepracon/Cobastudios/releases/latest`.
6. **Pricing integrity:** saved estimates deliberately reopen with the rates in effect when quoted. Don't "fix" that. Validated real-world costs (from invoices/job logs) beat assumed defaults — flag before changing any calibrated number.
7. **Flag regressions and drift.** If a request contradicts an earlier decision or these rules, say so before doing it.

## End-of-session ritual
